# Owner-approved localhost self-deposit

The owner explicitly authorized preparation of **one 0.005 SUI (5,000,000 MIST) self-deposit on Sui Mainnet**, with sender, recipient and gas owner all the existing Wallet A, and a **maximum 0.002 SUI gas budget**. Wallet B must be absent. Actual transaction review/approval remains in the owner's existing Slush account. This authorization does not cover x402, other transfers, new wallets or retries after failure/uncertainty.

The standalone tool defaults to review mode. Active signing requires the explicit local process argument `--owner-approved-signing` plus an ignored, private `authorization.json` that matches the freshly simulated BCS hash, exact owner address, asset, chain, amount, gas budget and expiry. The operator recorded the owner's authorization locally; the source contains no hardcoded owner address or key. The server refuses hosted/Vercel execution and binds only to loopback. Production PayGuard wallet policy and both false payment switches are untouched.

## Owner steps

1. Reload `http://localhost:4318`. Reconnect the same existing Slush account if the reload clears the page's connection state. Existing Google login stays inside Slush. Verify “Wallet A matches exactly” and the refreshed simulation, full address, 0.005 SUI and 0.002 SUI maximum gas budget.
2. Click **Validate Wallet A and unlock one signing attempt**. This durably reserves the one attempt; it does not sign or submit. Keep this tab open. Reloading after unlocking deliberately does not offer another signature request.
3. Click **Review and sign exact conversion in Slush**. Inspect the actual Slush transaction. It must contain only a split of 5,000,000 MIST and `0x2::coin::send_funds<0x2::sui::SUI>` to Wallet A, with Wallet A paying gas within the cap. Reject any different account, recipient, amount, command or security warning. No recovery phrase/private key is requested. Exact Slush labels and Google proof prompts vary by version.
4. Approve inside Slush only if the transaction matches. The tool requires sign-only `sui:signTransaction`, checks byte equality, and verifies the signature cryptographically for Wallet A (including zkLogin via the official SDK). There is no silent Sign-and-Execute fallback. A valid signature is stored privately with mode 0600; it is not printed or placed in browser storage. Signing alone does not submit through this tool. Application expiry does not revoke a disclosed signature's on-chain validity.
5. Once the page says the exact signature is verified, click **Submit this signed conversion once** if ready. This is the only execution trigger. The local server persists the submission state before its single official Mainnet execution RPC; SDK executor retries and gRPC retries are disabled. Slush's sign-only prompt might describe a Move interaction rather than an ordinary transfer, because both sides are Wallet A.
6. The tool checks the existing digest through independent **Tatum native Mainnet gRPC**. The page displays the actual finalized checkpoint, status, gas and updated native SUI total/coin/address balances only when independently proven. If pending, failed or uncertain, use **Check existing digest through Tatum · no resend**. Do not sign another transaction or retry submission. A failure may still consume gas.

Durable local files under ignored `.data/sui-self-deposit/` include the frozen `attempt-preview.json`, `attempt.json`, private signed payload and Tatum observations. No reset/delete workflow is provided. `sui:deposit:preview` refuses to overwrite the preview after an attempt exists. Server restart, cancellation, signature failure, double clicks and uncertain responses cannot reopen submission. Successful/final-failure evidence is retained. Read-only `npm run sui:deposit:verify -- ACTUAL_DIGEST` uses the frozen attempt snapshot, not a later preview.
